## 1. MODS — Windows 11 골든이미지 업데이트/Recompose 패키지

### 근거
- MODS 현재 상태에서 `Windows 11 업데이트/Recompose 계획`이 미완으로 남아 있음.
- VDI 운영에서 골든이미지 업데이트, 테스트 VM 검증, Recompose 일정 수립은 장애 리스크가 있어 유상 작업으로 분리하기 좋음.

### 상품화 방향
- 사전 영향도 분석
- 골든이미지 업데이트 절차서
- 테스트 VM 선적용 및 검증
- Recompose 작업계획서/체크리스트
- 야간/주말 작업 지원
- 작업 완료 보고서

### 제안 문구 초안
> Windows 11 업데이트 및 Recompose는 사용자 영향도가 있는 작업이므로 정기점검 범위가 아니라 별도 작업계획·사전검증·야간반영·결과보고 형태로 진행하는 것을 권장드립니다. 1차로 테스트 풀 기준 검증 후 단계적으로 운영 풀에 반영하는 방식으로 작업계획서를 준비하겠습니다.

### 다음 액션
- 5월 MODS 월간점검에서 대상 풀/VM 수, 작업 가능 시간대, 롤백 기준 확인.

## 2. SFD — VDI 공유 스토리지/ESXi 8/vCenter 8 마이그레이션

### 근거
- SR002가 이미 진행 중이며 시나리오가 확정됨.
- 기존 vCenter 6.7은 EOL 상태로 확인됨.
- Unity/FC SAN/ESXi 8/vCenter 8/Cold Migration/HA 검증까지 범위가 명확함.

### 상품화 방향
- 상세 작업계획서 v1.0
- 7-Phase 마이그레이션 수행
- vCenter 8 신규 구축
- ESXi 8.0 U3 클린 설치/클러스터 구성
- FC 멀티패스/HA/부팅스톰 검증
- 완료보고서

### 제안 문구 초안
> 현재 확정된 FC SAN 기반 이관 시나리오는 단순 점검이 아니라 운영 VDI 플랫폼 재구성 작업입니다. vCenter 6.7 EOL 해소, ESXi 8 통일, Unity 기반 공유스토리지 전환, Cold Migration 검증까지 포함하여 별도 SOW와 작업계획서 기준으로 진행하는 것이 안전합니다.

### 다음 액션
- 미확인 항목: DL380 CPU/패치레벨, FC HBA 모델, Unity FC SLIC, 케이블, VM 디스크 총량, 작업 윈도우 확정.

- 야간 반영 및 접속 검증

## 4. KISTI — Horizon 인증서/UAG 적용 + 접속 오류 정리

### 근거
- SR003이 진행 중: UAG 중간인증서 누락, fullchain.pem 생성 완료, UAG 적용 필요.

### 상품화 방향
- UAG 인증서 적용

### 다음 액션

## 5. MODS — VDI 대용량 통계 데이터 성능 진단/개선 컨설팅

### 근거
- SR006으로 제안서/진단 체크리스트/SAS·R 성능 설정 가이드가 이미 작성됨.
- 고객 제출 및 현장 진단이 남아 있음.
- 통계 데이터 100GB/GIS/Python 분석 검토 항목도 존재.

### 상품화 방향
- 현장 진단 1~2일
- SAS/R/Python 임시공간 및 I/O 병목 분석
- VM 리소스/스토리지 IOPS/Datastore 상태 점검
- 개선안 보고서
- 필요 시 별도 구축 작업 제안

### 제안 문구 초안
> 대용량 통계 데이터 처리 성능은 단순 VM 증설만으로 해결하기 어렵고, SAS/R/Python 임시공간, 스토리지 I/O, VM 리소스 정책을 함께 봐야 합니다. 기존 작성한 진단 체크리스트를 기준으로 1차 현장 진단을 별도 작업으로 진행하는 것을 제안드립니다.

### 다음 액션
- 고객에게 기존 제안서 제출 여부 확인 후, 성능 불만 사례/대상 업무를 2~3개 수집.

## 6. MODS — 지역센터 IP 관리 체계 수립

### 근거
- `지역센터 IP 관리 체계 수립`이 미완으로 남아 있음.
- 지역센터가 많을수록 Excel 기반 관리 한계와 IP 충돌 리스크가 있음.

### 상품화 방향
- IP 대역 현황 정리
- 운영 표준 수립
- Excel 표준안 또는 phpIPAM/NetBox 구축안
- 변경 이력 관리 방식 수립

### 제안 문구 초안
> 지역센터 IP 관리가 문서/담당자 기억에 의존하면 장애 대응과 장비 교체 시 충돌 리스크가 커집니다. 우선 Excel 표준안으로 빠르게 정리하고, 필요 시 phpIPAM/NetBox 같은 IPAM 도구로 확장하는 2단계 방식을 권장드립니다.

## 7. DJGLASS — 방화벽 장애 원인분석 + 이중화/교체 검토

### 근거
- 전사 인터넷 장애가 방화벽 강제 재부팅으로 복구되었으나 근본 원인 미해결.
- 단일 방화벽이며 이중화 없음.

### 상품화 방향
- 로그/펌웨어/세션/리소스 진단
- 장애 원인 분석 보고서
- 펌웨어 업그레이드 또는 장비 교체 권고
- 이중화 구성 검토서

### 제안 문구 초안
> 지난 장애는 재부팅으로 복구되었지만 원인 분석이 되지 않으면 동일 장애가 재발할 수 있습니다. 특히 전사 인터넷이 단일 방화벽에 의존하고 있어, 로그/펌웨어/세션 상태 진단과 이중화 또는 교체 검토를 별도 진단 작업으로 진행하는 것을 권장드립니다.

## 8. SFD — 백업 솔루션 별도 SOW

### 근거
- SR002에서 백업 항목은 범위 제외로 환원됨.
- Veeam Community 공공기관 리스크로 유료 또는 국산 백업 검토 권고가 기록됨.

### 상품화 방향
- 백업 요구사항 정리
- Veeam Foundation/Essentials 또는 국산 백업 비교
- 복원 시험 절차서
- 별도 구축/운영 견적

### 제안 문구 초안
> 이번 스토리지 이관 작업과 별개로, 운영 안정성을 위해 백업 정책과 복원 시험 체계를 별도 SOW로 검토하는 것을 권장드립니다. Community Edition은 공공기관 운영/지원 측면의 리스크가 있어 유료 또는 국산 백업 솔루션 기준으로 비교안을 준비하겠습니다.

## 정정 메모 — 현우님 확인 반영

- SFD 공유스토리지/ESXi 8/vCenter 8 구축 건은 이미 수주 및 구축 완료.
- MODS Windows 11/Recompose는 이미 다른 업체가 수주했으며 2026년 5월 중 진행 예정.
- KRIHS/KISTI 인증서/UAG/접속오류 등 일반 운영성 작업은 대부분 기존 유지보수 범위에 포함되어 별도 비용 청구가 어려움.

## 다시 봐야 할 방향

1. **기존 고객 추가 과금**은 “유지보수 범위 밖”이어야 함.
   - 신규 장비/라이선스 납품
   - 명확한 구축/마이그레이션
   - 신규 기능 도입
   - 별도 산출물/컨설팅 계약
   - 유지보수 계약에 없는 야간/긴급/상주성 작업

2. **현실적인 매출 방향은 신규 고객/신규 계약 발굴** 쪽이 더 큼.
   - 공공기관 VDI 유지보수 공고 감시
   - Citrix/Omnissa/VMware EOS/EOL 기반 교체 수요 발굴
   - 기존 고객사의 장비·라이선스 갱신/증설 트리거 추적
   - 총판/협력사에 보낼 “VDI 유지보수 수행 가능 범위” 소개자료 작성

## 바로 실행할 3개 — 수정안

1. **나라장터/공공기관 VDI 유지보수 신규 공고 감시 키워드 정리**
2. **협력사/총판에 보낼 현우님 VDI 유지보수 역량 소개서 작성**
3. **기존 고객별 라이선스·장비 갱신/교체 트리거만 별도 추적표로 분리**
